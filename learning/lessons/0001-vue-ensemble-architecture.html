Leçon 0001 · ~8 minutes · liée à la mission

En une phrase

Cette extension VS Code est un client ACP : elle lance (ou isole) un agent IA, envoie tes prompts via JSON-RPC, affiche les réponses dans une webview React, et indexe les conversations passées dans l'arbre Agents.

Source : Agent Client Protocol · README.fr.md

Démarrage de l'extension

Quand VS Code charge l'extension, le chemin est court et linéaire :

src/extension.ts
  └─ activate() → startExtensionRuntime()
       ├─ AgentManager, ConnectionManager, SessionManager
       ├─ SessionTreeProvider  (vue arbre « Agents »)
       ├─ ChatWebviewController + React webview  (panneau « Chat »)
       ├─ registerCommands()  (Connect, Send, New Conversation…)
       └─ plugins optionnels :
            OrchestrationPlugin  (.acp/pipelines, .acp/teams)
            SandcastlePlugin     (bridge Docker)
            InlineChatPlugin     (Cmd+I)

SessionManager est le cœur runtime : il possède la Conversation active, parle au ConnectedAgent, et émet des événements que la webview écoute (active-session-changed, clear-chat, etc.).

Parcours utilisateur typique

  1. Tu choisis un ConfiguredAgent dans l'arbre (ex. « Claude Code »).
  2. Connect → ConnectionManager spawn le processus ACP (ou le bridge Sandcastle).
  3. Tu envoies un prompt → le client ACP stream des session/update.
  4. SessionUpdateHandler transforme le flux en ChatHistory (UI riche).
  5. En parallèle, un SessionRecord est mis à jour pour l'arbre et le handoff.
Piège fréquent — le mot « session »
Il désigne au moins quatre choses différentes. Voir le glossaire : ProtocolSession, Conversation, SessionRecord, BridgeConversation.
